AGENTIC HRMS — INDUSTRY-LEVEL BUILD PLAN (7 hrs/day, 25 working days ≈ 175 hrs)
Role-Based AI-Powered HR Management System with Agentic AI + RAG + CI/CD
================================================================================

HOW TO USE THIS FILE (read this first — for the AI coding agent AND for Mohit)
--------------------------------------------------------------------------------
- Work ONE DAY at a time, top to bottom. Each day has GOAL, TASKS, DELIVERABLE,
  DONE-WHEN. A day is only done when DONE-WHEN passes AND the app still runs
  end-to-end — never move on with a half-broken state committed to main.
- 25 working days ≈ 4 weeks at 6 days/week, or ~3.5 weeks at 7 days/week.
  Pick a sustainable pace over hitting an exact week count.
- Git discipline: one feature branch per day, PR into main, merge only when
  CI passes (CI is set up on Day 7 — until then, just keep main always
  runnable). This IS how real teams work, so treat it as practice, not
  ceremony.
- Trade-offs made to fit this timeline (own these in interviews — they show
  judgment, not corner-cutting):
    - No Celery/background jobs — leave accrual etc. handled synchronously.
    - Test coverage is built into each day for the highest-risk logic (auth,
      RBAC, agent tool permission checks) rather than a single dedicated
      100%-coverage day.
    - Frontend polish is one focused pass (Day 13), not spread across every
      module.
    - IaC (Terraform) and deep observability are OUT of scope for v1 — noted
      as "v2" ideas at the end of this file.
  If you finish early, spend extra time in this order: test coverage > RAG
  tuning > frontend polish > IaC/observability.

TECH STACK
================================================================================
BACKEND
  - Python 3.11+, FastAPI, Uvicorn
  - PostgreSQL 15+ (Docker) + pgvector extension (doubles as your vector DB —
    no separate Chroma/Pinecone instance to run)
  - SQLAlchemy 2.0 (async), Alembic migrations, Pydantic v2
  - Auth: JWT (python-jose) + passlib[bcrypt]
  - RBAC: custom permission-matrix + FastAPI dependency (not a 3rd-party lib —
    you want to be able to explain every line of this in an interview)
  - Agentic AI: LangGraph (supervisor pattern) + LangChain tool-calling
  - LLM: OpenAI gpt-4o-mini, behind a provider interface (swappable later)
  - Testing: pytest + httpx (async test client)
  - Linting/formatting: ruff + black
  - Containerization: multi-stage Dockerfile (dev + slim prod stage) +
    docker-compose (api, postgres, redis if kept)

FRONTEND
  - React 18 + Vite, TypeScript
  - TailwindCSS + shadcn/ui (Radix-based)
  - React Router v6
  - TanStack Query + Axios
  - Redux(client/auth state)
  - React Hook Form + Zod
  - Recharts
  - Linting/formatting: eslint + prettier

DEVOPS / CI-CD (new in this version — this is what makes the project read as
"industry-level" rather than "solo tutorial project")
  - GitHub Actions: CI pipeline (lint + test + build) on every push/PR to
    both backend and frontend, required to pass before merging to main
  - Pre-commit hooks: ruff/black (backend), eslint/prettier (frontend) — catch
    style issues before they even reach CI
  - Multi-stage Docker builds: separate dev vs. slim production images
  - Environment separation: dev/staging/prod config via pydantic-settings,
    secrets via GitHub Actions secrets (never committed), `.env.example`
    committed instead of real `.env`
  - CD: GitHub Actions auto-deploys backend on merge to main (Render/
    Railway/Fly.io); frontend auto-deploys via Vercel's native git
    integration; Alembic migrations run as an explicit pipeline step before
    the new backend version goes live
  - Basic observability: structured JSON logging, a real health-check
    endpoint the hosting platform pings, and a rollback note in the README
    (how to redeploy the previous image if a deploy breaks something)

REPO LAYOUT (create on Day 1, DevOps folders added Day 7)
  agentic-hrms/

WEEK 1 — BACKEND CORE + CI/CD FOUNDATIONS  (Days 1-7)
================================================================================
DAY 1 — Setup + data model + seed
TASKS:

    skeleton with health check, Vite+React+Tailwind+shadcn frontend shell.
  - SQLAlchemy models: User, Role, Department, Designation, Employee,
    TimestampMixin. Alembic migration. Seed script (1 admin, 2 depts,
    3 designations).
DONE-WHEN:
  [ ] docker-compose up -d works clean; alembic upgrade head runs clean
  [ ] health check returns 200; frontend shell renders

DAY 2 — Auth + RBAC
TASKS:
  - POST /auth/login (JWT access+refresh), password hashing,
    get_current_user dependency, POST /auth/refresh.

    require_permission() dependency built on top of it.
DONE-WHEN:
  [ ] Login works, protected routes reject bad/missing tokens
  [ ] Employee gets 403 / HR gets 200 on a dummy role-gated route

DAY 3 — Employee + Department/Designation modules
TASKS:

    all, filterable by department).
  - Department/Designation CRUD (Admin-only writes, everyone reads).
  - pytest for auth + RBAC + employee CRUD.
DONE-WHEN:
  [ ] Full CRUD demoable via /docs for both modules, role scoping verified
  [ ] pytest green for auth/RBAC/employee

DAY 4 — Attendance
TASKS:

DONE-WHEN:
  [ ] Full attendance flow works; correction blocked for Employee role

DAY 5 — Leave management (full lifecycle)
TASKS:
  - LeaveType/LeavePolicy (Admin CRUD), LeaveBalance (auto-init on employee
    creation), LeaveRequest workflow (apply/approve/reject/cancel), balance
    decrements on approval.
DONE-WHEN:
  [ ] Full leave lifecycle works end-to-end against seed data

DAY 6 — Remaining backend modules (priority order — cut from bottom if tight)
TASKS:
  1. Policy document storage (upload/list/get — metadata layer for RAG)
  2. Dashboard/analytics endpoints per role
  3. Holidays + Announcements CRUD
  4. Admin user/permission management (create HR/Employee accounts,

DONE-WHEN:
  [ ] Items 1-2 fully working (non-negotiable — frontend and RAG depend on
      them). Items 3-4 done if time allows; otherwise carry into Week 2 slack.

DAY 7 — CI/CD & DevOps foundations
TASKS:
  - GitHub Actions CI workflow (.github/workflows/ci.yml): on push/PR, run

  - Convert backend Dockerfile to multi-stage (builder stage + slim runtime

  - Environment separation: pydantic-settings config classes for
    dev/staging/prod, `.env.example` committed, real `.env` gitignored.
    docker-compose.prod.yml for a production-shaped local test.
  - Structured JSON logging setup (so it's ready before you have much to log).
DONE-WHEN:
  [ ] Opening a PR triggers CI automatically and shows pass/fail
  [ ] main is protected — cannot merge with failing CI
  [ ] `docker build` succeeds using the multi-stage Dockerfile and produces
      a noticeably smaller image than the dev one
  [ ] pre-commit run --all-files passes clean

** MILESTONE: backend feature-complete AND wrapped in a real CI pipeline —
   this is the point where the project stops looking like a tutorial repo. **

WEEK 3 — RAG PIPELINE + AGENTIC AI ORCHESTRATION  (Days 14-20)
================================================================================
DAY 14 — RAG ingestion pipeline
TASKS:
  - Enable pgvector, DocumentChunk model, ingestion service (extract text,
    chunk with overlap, embed via OpenAI embeddings, store vectors). Trigger
    automatically on policy doc upload.
DONE-WHEN:
  [ ] Uploading a policy PDF produces chunks + embeddings in the DB

DAY 15 — Retrieval + grounded generation
TASKS:
  - similarity_search(query, top_k) via pgvector. LLM wrapper whose system
    prompt forces answers ONLY from retrieved context, cites the source doc,
    and says "I don't know" when context is insufficient.
DONE-WHEN:
  [ ] /rag/ask gives a grounded, cited answer for an in-corpus question, and
      correctly says "I don't know" for an out-of-corpus one

DAY 16 — RAG eval + agent architecture setup
TASKS:
  - Morning: 10-question eval set from your uploaded docs, tune chunk
    size/top_k until 8+/10 correct.
  - Afternoon: LangGraph skeleton — Supervisor routing to RAG Agent /
    Database Agent / Action Agent / Response Generator, shared state design
    (user_id, role, history, intent, tool results).
DONE-WHEN:
  [x] RAG eval passes 8+/10; graph compiles and routes correctly to stubs

DAY 17 — Database Agent + RAG Agent wired in
TASKS:
  - Read-only tools (get_leave_balance, get_attendance_summary,
    list_employees, get_employee_details) that ALWAYS take user/role from
    graph state, never from LLM free text.
  - Wrap Day 15's RAG pipeline as a graph node/tool.
DONE-WHEN:
  [x] "How many leaves do I have left?" and "What's the WFH policy?" both
      route correctly and return scoped/grounded answers

DAY 18 — Action Agent (CRUD tools) + permission enforcement
TASKS:
  - Tools: create/update/delete_employee, approve/reject_leave,
    create_department, etc. — every tool calls the SAME require_permission
    logic from Day 2.
DONE-WHEN:
  [x] Employee asking to delete an employee is rejected server-side with no
      DB write; HR/Admin equivalents succeed

DAY 19 — Slot-filling + sensitive action confirmation + memory
TASKS:
  - Missing-field follow-up loop for CREATE/UPDATE requests.
  - Confirmation step for destructive/bulk actions.
  - Short-term conversation memory, strictly scoped per authenticated user.
DONE-WHEN:
  [x] "Add employee Priya Singh" (missing fields) asks a follow-up and
      completes correctly after the answer
  [x] "Delete all test employee records" requires confirmation before acting
  [x] Two different users never see each other's conversation context

DAY 20 — Full agent scenario testing
TASKS:
  - Run all 4 example scenarios from the project doc (policy question, leave
    query, HR creates employee, unauthorized delete) exactly as written.
    Fix routing/misclassification bugs. Small intent eval set (10-15 prompts).
DONE-WHEN:
  [x] All 4 doc scenarios produce the documented outcome via API calls
  [x] Intent eval passes 8+/10

SUMMARY
================================================================================
25 working days x 7 hrs ≈ 175 hours.
  Week 1 (Days 1-7):   Backend core + CI pipeline
  Week 2 (Days 8-13):  Frontend — foundations + every module's UI
  Week 3 (Days 14-20): RAG pipeline + full agentic AI orchestration
  Week 4 (Days 21-25): Chat UI integration, audit, security, CD + deploy

Checkpoints: Day 7 (backend + CI live), Day 13 (full HRMS demoable via UI),
Day 20 (agent verified via API), Day 25 (live, auto-deploying, documented).

WHAT MAKES THIS "INDUSTRY-LEVEL" VS. A TYPICAL PORTFOLIO PROJECT:
  - Real RBAC enforced server-side at the tool layer, not just hidden UI buttons
  - Agent tools never trust the LLM for identity/permissions — always pulled
    from authenticated session state
  - CI required to pass before merge (not just "it works on my machine")
  - Multi-stage Docker builds, environment separation, secrets management
  - Automatic CD with a documented rollback path
  - Audit logging covering both human and AI-driven actions
  - Grounded RAG with explicit "I don't know" handling instead of hallucinating

v2 IDEAS (out of scope for this build, good "what I'd do next" interview
answers):
  - Terraform/IaC for the Postgres + hosting resources
  - Centralized observability (e.g. shipping logs/metrics to a real
    dashboard instead of relying on the hosting platform's console)
  - Celery + Redis for async jobs (leave accrual, reminder emails)
  - Blue-green or canary deploys instead of a single-shot CD step
